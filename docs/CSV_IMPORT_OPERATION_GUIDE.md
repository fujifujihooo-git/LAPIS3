# LAPIS3 顧客CSVインポート 運用・ロールバック手順書 (v2)

作成日: 2026-08-21  
対象機能: 顧客CSVインポート機能  
対象読者: システム管理者・事務運用担当者

---

## 1. 現場運用チェックシート

業務でのインポート事故を防ぐため、以下のチェックリストに沿って運用を実施してください。

### 📋 【取込前】チェックリスト
* [ ] **本番バックアップ取得**: 直前のFirestoreバックアップ（`backup.js`）が取得されているか確認。
* [ ] **Excelフィルター解除**: 抽出・絞り込み中のままCSV出力していないか（全データが出力されているか）確認。
* [ ] **CSVファイル件数確認**: 想定している移行件数（例: 250件）とCSVの行数が合致しているか確認。
* [ ] **必須列の存在確認**: 1行目に `顧客名`（または `customer_name`）が存在するか確認。
* [ ] **法人番号列の書式確認**: 先頭の `0` が落ちて12桁になっていないか（文字列書式で保存されたか）確認。

---

### 📋 【プレビュー中】チェックリスト
* [ ] **文字コード認識確認**: プレビューヘッダーで文字化けがなく、`UTF-8` または `Shift-JIS` と正しく表示されているか。
* [ ] **🔴 エラー件数の確認**: エラー件数が `0` か、あるいは想定内の除外データ（顧客名なし等）のみか確認。
* [ ] **🟡 警告件数の確認**: 同名顧客や既存法人番号重複、区分未指定の内容を確認し、登録して問題ないか判断。

---

### 📋 【取込後】チェックリスト
* [ ] **完了ダイアログの確認**: 表示された「バッチID」「成功件数」「採番範囲」を記録（メモ）。
* [ ] **登録件数の突合**: 顧客一覧画面の総件数が、インポートした件数分だけ正確に増加しているか確認。
* [ ] **顧客検索確認**: 取り込んだ主要な顧客名（または法人格を除いた部分一致）で検索し、正常にヒットするか確認。
* [ ] **詳細画面確認**: 1〜2件の顧客詳細画面（`customer_detail.html`）を開き、住所・電話番号・区分が正しく表示されるか確認。

> [!TIP]
> もし列ずれや古いCSVの誤投入に気づいた場合は、直ちに完了ダイアログの「バッチID」を用いてロールバック（一括削除）を実行してください。

---

## 2. 誤取込時のロールバック（リカバリ）手順

万が一、列ずれしたCSVや誤ったデータを一括登録してしまった場合は、以下の手順で復元・削除を行えます。

### 方法A: バッチID指定による一括削除（★推奨・最も安全）

インポート完了時のダイアログに表示された **「バッチID: imp_YYYYMMDD_HHMMSS_xxxxx」** を指定して、その取込で生成された顧客レコードだけを100%安全にピンポイント削除します（他の通常登録データや別バッチのデータを誤削除する心配がありません）。

#### ステップ1: 事前確認（DRY-RUN）
実際の削除を行わずに、対象データを確認します。
```bash
node scripts/rollback_imported_customers.js --batch-id imp_20260821_154500_abc12 --dry-run
```

#### ステップ2: 一括削除実行
確認後、実際に削除を実行します（100件単位で安全に分割バッチ削除されます）。
```bash
node scripts/rollback_imported_customers.js --batch-id imp_20260821_154500_abc12
```

---

### 方法B: customer_id 範囲指定による一括削除

採番範囲（例: `ID 1002 〜 1101`）を指定して削除します。
```bash
node scripts/rollback_imported_customers.js --start 1002 --end 1101 --dry-run
node scripts/rollback_imported_customers.js --start 1002 --end 1101
```

---

### 方法C: 画面からの個別削除（数件の場合）

数件の誤登録であれば、顧客一覧画面から該当顧客の詳細画面（`customer_detail.html?id=XXXX`）を開き、フッターの **「削除」** ボタンから削除できます。

---

## 3. 部分成功時（途中で失敗した場合）の再実行フロー

万が一、通信障害等で 250件中 100件が登録成功し、101件目以降が失敗した場合の推奨リカバリ手順です。

```text
【部分失敗発生】 (100件成功 / 150件失敗)
       ↓
【推奨選択肢 ①: 一旦ロールバックして再投入】
  1. 完了時に表示されたバッチIDで一旦ロールバックを実行（成功した100件を削除）
  2. CSVデータや通信環境を確認の上、再度CSV全体を取り込む。
       ↓
【推奨選択肢 ②: 失敗分のみ取り込み】
  1. そのまま同一CSVを再選択すると、登録済みの100件は「🟡 既存顧客と法人番号/同名一致」として警告表示される。
  2. 二重登録を防ぐため、未登録の150件のみを抽出したCSVを作成して投入する。
```

---

## 4. ロールバック後の連番カウンターについて

一括削除を実行しても、`counters/customers` の値は巻き戻りません（欠番となります）。  
LAPIS3の `customer_id` は内部管理用の一意なサロゲートキーであり、欠番が存在してもシステム動作上の支障は一切ありません。
