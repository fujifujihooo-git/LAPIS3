# LAPIS3 顧客CSVインポート機能 基本設計書 v0.3.1（確定版）

作成日: 2026-08-21
ステータス: **確定（凍結）**
対象システム: LAPIS3
機能名: 顧客CSVインポート機能

---

## 1. 目的

既存システムやExcelで管理されている顧客情報を、LAPIS3へ一括登録する。
安全なプレビュー方式と現場目線の重複警告により、誤登録や重複作成事故を防止する。

---

## 2. 開発方針

- **ターゲット**: 事務職員・行政書士スタッフ
- **安全性優先**: 「取込 → 解析 → プレビュー（重複・警告確認） → 登録実行」の4段階フロー
- **UI/UX原則**: LAPIS3 UIデザイン規約準拠（3秒で状況把握、サマリーカード、状態別カラーバッジ）

---

## 3. スコープ

- **対象**: 顧客マスタ（`customers` コレクション）
- **対象外**: 許認可情報、案件情報、請求情報、入金情報、インポートログ

---

## 4. 業務フロー

```
[顧客一覧画面]
      ↓ 「CSVインポート」ボタン押下
[インポートダイアログ]
      ↓ CSVファイル選択
[CSV自動解析（文字コード判定・クレンジング）]
      ↓
[プレビュー・重複判定]
      ├─ 判定バッジ（🟢 正常 / 🟡 警告 / 🔴 エラー）
      ├─ サマリー表示（総件数・正常・警告・エラー）
      └─ 絞り込みタブ（すべて / 警告のみ / エラーのみ）
      ↓
[登録実行（エラー行を除外して一括登録）]
      ↓
[完了通知＆一覧自動リロード]
```

---

## 5. CSV仕様

### 5.1 ファイル基本仕様

- **文字コード**: UTF-8（BOM有無対応）および Shift-JIS (CP932) 自動判別
- **区切り文字**: カンマ（`,`）
- **ヘッダ行**: 必須（1行目）

### 5.2 項目マッピング定義

| CSVヘッダ名 | 日本語名 | 必須 | LAPIS3 Firestore項目 | バリデーション＆補正ルール |
|---|---|:---:|---|---|
| `customer_name` (または `name` / `顧客名`) | 顧客名 | 〇 | `customer_name` | 空白不可。前後の余白は自動トリム |
| `customer_kana` (または `kana` / `フリガナ`) | フリガナ | | `customer_kana` | 全角カタカナ |
| `customer_type` (または `区分`) | 顧客区分 | | `customer_type` | 「法人」または「個人」。未指定時の扱いは §6 参照 |
| `representative_name` (または `代表者名`) | 代表者名 | | `representative_name` | 文字列 |
| `corporate_number` (または `法人番号`) | 法人番号 | | `corporate_number` | 半角数字13桁。全角数字は自動半角化 |
| `postal_code` (または `郵便番号`) | 郵便番号 | | `postal_code` | 半角数字（7桁）。ハイフン有無両対応（自動整形） |
| `address` (または `住所`) | 住所 | | `address` | 文字列 |
| `building_name` (または `建物名`) | 建物名 | | `building_name` | 文字列 |
| `phone` (または `電話番号`) | 電話番号 | | `phone` | 半角数字・ハイフンに自動補正 |
| `fax` (または `FAX番号`) | FAX番号 | | `fax` | 半角数字・ハイフンに自動補正 |
| `email` (または `メールアドレス`) | メールアドレス | | `email` | メールアドレス形式チェック |
| `remarks` (または `memo` / `備考`) | 備考 | | `remarks` | 文字列 |

### 5.3 サンプルCSV

```csv
customer_name,customer_kana,customer_type,representative_name,corporate_number,postal_code,address,building_name,phone,fax,email,remarks
株式会社サンプル,カブシキガイシャサンプル,法人,代表 太郎,1234567890123,100-0001,東京都千代田区1-1-1,サンプルビル5F,03-1234-5678,03-1234-5679,info@sample.co.jp,移行データ
鈴木 一郎,スズキ イチロウ,個人,鈴木 一郎,,150-0002,東京都渋谷区2-2-2,,090-1234-5678,,ichiro@example.com,個人事業主
```

## 6. バリデーション＆判定マトリクス

### 判定ステータス

| 区分 | 判定条件 | 登録可否 | 運用上の位置づけ |
|---|---|:---:|---|
| **🔴 エラー** | ・`customer_name` が空欄<br>・法人番号が13桁数字以外（12桁など） | ×<br>(自動除外) | システム整合性・名寄せの根幹に関わるため除外 |
| **🟡 警告** | ・**法人番号が既存顧客と重複**<br>・**顧客名が既存顧客と完全一致**<br>・**CSVファイル内で重複（法人番号/顧客名）**<br>・`customer_type` 未指定かつ法人番号なし（→ `未設定` で保存）<br>・`customer_type` が未定義の文字列（`個人事業主` 等 → `未設定` で保存）<br>・`email` の形式不正（登録後に詳細画面で修正可能） | 〇<br>(登録可) | 実務での業務停止防止＆後から修正可能な項目 |
| **🟢 正常** | エラー・警告のいずれにも該当しない | 〇<br>(登録可) | スムーズにそのまま一括登録 |

### customer_type 判定ルール（確定）

| 条件 | 保存される customer_type | 判定 |
|---|---|---|
| CSV に `法人` または `個人` を指定（空白トリム後） | `法人` または `個人` | 🟢 正常 |
| CSV に `customer_type` 未指定 ＆ 法人番号あり | `法人` | 🟢 正常 |
| CSV に `customer_type` 未指定 ＆ 法人番号なし | **`未設定`** | 🟡 警告（「区分未指定（法人番号なし）のため『未設定』として登録します」） |
| CSV に `個人事業主` や `法人会社` 等の未定義文字列 | **`未設定`** | 🟡 警告（「区分『○○』は未定義のため『未設定』として登録します」） |

## 7. 画面設計

### 7.1 顧客一覧画面

「新規顧客登録」ボタンの左隣に `[📥 CSVインポート]` ボタンを配置。

### 7.2 プレビューモーダル

1. **サマリーカード**: 総件数・正常・警告・エラーの件数表示
2. **絞り込み**: すべて / 警告のみ / エラーのみ
3. **プレビューテーブル**: 行番号・状態・顧客名・区分・法人番号・電話番号・判定理由
4. **アクションフッター**: キャンセル / エラーを除外して○件を登録

---

## 8. Firestore 登録仕様

### 8.1 一括採番

`counters/customers` から登録対象件数分を1回のトランザクションでまとめて発番。

### 8.2 ドキュメント構造

- ドキュメントID: `cust_${customer_id}`
- `status`: `'稼働中'`（固定初期値）
- `created_date` / `last_updated`: ISO文字列
- `search_name` / `search_kana`: 検索用自動生成フィールド

### 8.3 バッチ書き込み

**100件単位**で分割バッチ書き込み（Chunked Batch）。
500件ギリギリを攻めない。デバッグ性・エラー切り分け・将来拡張性を優先。

---

## 9. 非機能要件

- 1回あたり最大 500件（推奨）、リミッター上限 1,000件
- 100件 / 30秒以内（目標）
- 既存の顧客登録権限に準拠（専用権限は設けない）

---
